# Verse Garden — Android app (APK)

The Android app is a **native shell** (Capacitor) around the same web app
that runs at https://ppp65isking.github.io/note-bible/. It is NOT a
different app: your notes, diary, themes and Firebase account are the same.

## What the native app adds over the web version

- **Fingerprint / face unlock** — turn on the app passcode in Settings,
  and the app offers your fingerprint or face first (your device PIN /
  pattern / password is the fallback). The 4-digit PIN pad is still there
  if biometry is cancelled or unavailable. On the web, the passcode is
  PIN-only, exactly as before.
- **Google sign-in, natively** — the "Continue with Google" button signs
  in with the native Google account picker (no browser redirect). Email +
  password sign-in works too, same as the web.
- **Haptics** — a light tap buzz on bottom-bar tabs, a firmer one on the
  quick-add (+) button.
- **Status bar tint** — the Android status bar matches your theme accent.
- **Splash screen** — the Verse Garden icon shows while the app loads.
  The app can never get stuck on it: if anything goes wrong while
  starting up, the splash hides itself after a few seconds anyway.
- A real installed app in the app drawer, with our own icon, instead of
  a browser shortcut.

## How the APK gets built

Pushing to `main` (or running the workflow by hand) builds it:

1. Push any change to the web files or the workflow itself.
2. GitHub Actions runs **Build Android APK** (`.github/workflows/build-apk.yml`):
   Node 22 → `npm ci` → build `www/` from the repo-root web files →
   `npx cap add android` (generates the native project fresh) →
   enable the Google Sign-In libraries for Firebase Auth →
   `npm run assets:generate` (launcher icon + splash from
   `icons/icon-512.png`) → decode `google-services.json` from the
   `ANDROID_GOOGLE_SERVICES_JSON` repo secret (skipped if the secret
   isn't set yet) → `npx cap sync android` → `./gradlew assembleDebug`.
3. When it finishes, open the run → **Artifacts** → download
   **verse-garden-apk** (a zip containing `app-debug.apk`).

You can also run it manually: repo → **Actions** → **Build Android APK**
→ **Run workflow**.

## How to install the APK on a phone

1. Download `app-debug.apk` onto the Android phone.
2. Tap the file. Android will ask to allow installs from that app
   (browser / Files) — allow it once, then tap **Install**.
3. Open **Verse Garden** from the app drawer and sign in as usual.

It is a **debug APK**: it installs directly and works fully, but it is not
signed with a release key, so it can never go on the Play Store as-is
(a release build + Play account is a separate step, if ever wanted).

## Updates

The APK loads the app code that was bundled into it at build time — so a
new feature or fix needs a **new build** (push → Actions → install the new
APK over the old one; your notes and account carry over, they live in
Firebase / on-device storage, not in the APK). The live website updates
independently and immediately; the APK does not auto-update from it.

## Notes / follow-ups

- **Google sign-in**: the native app signs in with Google through
  `@capacitor-firebase/authentication` (`signInWithGoogle()`), and the
  token is bridged into the web Firebase SDK so notes sync the same way.
  It needs two things that live OUTSIDE the repo:
  1. The repo secret **`ANDROID_GOOGLE_SERVICES_JSON`** — base64 of the
     `google-services.json` for project `verse-notes`, package
     `com.versegarden.app`. The workflow decodes it into
     `android/app/google-services.json` before building; without the
     secret the build still succeeds but Google sign-in won't work.
  2. **The signing key's SHA-1 in Firebase** — Google only accepts
     sign-in from an APK signed with a key whose SHA-1 is registered
     under the Android app in Firebase console. The debug APKs from
     Actions are signed with a fresh throwaway debug key on every run,
     so until the workflow signs builds with the project's persistent
     key (a separate step, via GitHub Secrets), native Google sign-in
     will answer `DEVELOPER_ERROR` and the app says so plainly. Email
     sign-in works regardless.
  The web redirect sign-in is unchanged.
- **App icon + splash**: generated every build by `@capacitor/assets`
  from `icons/icon-512.png` (see `scripts/prepare-assets.mjs` and the
  `assets:generate` npm script). The generated `resources/` folder is
  build-time only and is not committed.
- **Rebuilding locally** (needs Android Studio / SDK):
  `npm run sync` then open `android/` in Android Studio and Run.
  (`android/` is generated by `npx cap add android` and is not committed.)
  To regenerate icons locally: `npm run assets:generate`.
- **Files**: `capacitor.config.json` (app id `com.versegarden.app`,
  `FirebaseAuthentication` providers `["google.com"]`),
  `scripts/build-www.mjs` (copies root web files into `www/`),
  `scripts/prepare-assets.mjs` (copies `icons/icon-512.png` into
  `resources/` for `@capacitor/assets`).
