# Verse Garden — Android app (APK)

The Android app is a **native shell** (Capacitor) around the same web app
that runs at https://ppp65isking.github.io/note-bible/. It is NOT a
different app: your notes, diary, themes and Firebase account are the same.

## What the native app adds over the web version

- **Fingerprint / face unlock** — turn on the app passcode in Settings,
  and the app offers your fingerprint or face first (your device PIN /
  pattern / password is the fallback). The 4-digit PIN pad is still there
  if biometry is cancelled or unavailable. On the web, the passcode is
  PIN-only, exactly as before.
- **Haptics** — a light tap buzz on bottom-bar tabs, a firmer one on the
  quick-add (+) button.
- **Status bar tint** — the Android status bar matches your theme accent.
- **Splash screen** — the Verse Garden icon shows while the app loads.
- A real installed app in the app drawer, instead of a browser shortcut.

## How the APK gets built

Pushing to `main` (or running the workflow by hand) builds it:

1. Push any change to the web files or the workflow itself.
2. GitHub Actions runs **Build Android APK** (`.github/workflows/build-apk.yml`):
   Node 20 → `npm ci` → build `www/` from the repo-root web files →
   `npx cap add android` (generates the native project fresh) →
   `npx cap sync android` → `./gradlew assembleDebug`.
3. When it finishes, open the run → **Artifacts** → download
   **verse-garden-apk** (a zip containing `app-debug.apk`).

You can also run it manually: repo → **Actions** → **Build Android APK**
→ **Run workflow**.

## How to install the APK on a phone

1. Download `app-debug.apk` onto the Android phone.
2. Tap the file. Android will ask to allow installs from that app
   (browser / Files) — allow it once, then tap **Install**.
3. Open **Verse Garden** from the app drawer and sign in as usual.

It is a **debug APK**: it installs directly and works fully, but it is not
signed with a release key, so it can never go on the Play Store as-is
(a release build + Play account is a separate step, if ever wanted).

## Updates

The APK loads the app code that was bundled into it at build time — so a
new feature or fix needs a **new build** (push → Actions → install the new
APK over the old one; your notes and account carry over, they live in
Firebase / on-device storage, not in the APK). The live website updates
independently and immediately; the APK does not auto-update from it.
